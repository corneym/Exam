Backup, restore and data safety

Backup

Choose File → Backup Now... to create a manual full backup. It contains the Question Bank database and the complete managed Subject data tree, including imported Exam and Answer PDFs, curriculum assets and retained legacy workbooks.

A full backup is needed to recover both the database and its managed source files. It does not include the separate questionbank.properties settings file, documents held outside the managed Subject tree, or unrelated files elsewhere in the data root. Preserve those separately if you need them.

Normal application shutdown creates an automatic database-only backup, without source PDFs or other managed assets. The ten newest automatic database backups are retained. These are useful for database recovery but are not a substitute for full backups.

Keep independent full backups outside the active data directory, preferably in more than one location. Synchronising a data root between computers is not by itself a replacement for saved backups, because unwanted changes may be synchronised too.

Restore

Choose File → Restore Backup... to restore a supported application backup.

Current full backups use the Subject-first backup format. Older format-1 full backups containing separate PDF and curriculum data trees are not supported by this version and are rejected rather than translated or restored.

Restore replaces active application data with the contents of the selected backup. Read the confirmation information carefully before proceeding. A successful restore requires the application to restart before the restored data is used.

Before replacing data, the application creates a full safety backup of the current database and managed Subject files. If replacement fails, it attempts to restore the previous data from that backup. An unexpected power loss or forced termination cannot be assumed to complete this recovery.

If a restore reports that rollback also failed, do not continue using the affected data root. Preserve the safety backup and any independent full backups, and recover into a separate data root before resuming normal use.

Schema migration

The application manages database schema upgrades when opening data from supported earlier versions. Do not manually edit migration files or the application database.

Application exit

Use File → Exit or close the main application window normally so the application can complete its shutdown and backup workflow.
